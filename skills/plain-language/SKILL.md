# Plain Language

Rewrite the last answer so a capable non-specialist can understand it on the first read.

- Preserve the outcome, important evidence, uncertainty, limits, ownership, and next steps.
- Replace jargon with ordinary words. When a technical term is essential, explain it briefly.
- Remove repetition and internal process that does not help the user decide or act.
- Keep useful detail. Do not turn the answer into a TL;DR unless the user also asks for brevity.
- Do not change facts, inflate proof, invent progress, or silently collapse source, package, runtime, and live-user status.
- Put the practical conclusion first.
